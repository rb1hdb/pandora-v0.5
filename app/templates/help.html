02 — Architecture

▾
[User] ↓ [D1 Input Filter] — regex: SQL/XSS/delimiters/credentials [D2 Input Judge] — LLM classifies input as SAFE/UNSAFE ↓ [RAG — bge-m3 (in-memory)] — retrieves context from documents [D3 SP Lock] — appends protection to system prompt [D4 SP Alignment] — appends alignment to system prompt ↓ [LLM — Ollama] — generates response / triggers tools ↓ [MCP Client SSE] ──→ [MCP Server :55001] ──→ [catalog.json + /videos/] ↓ [D5 Output Judge] — LLM classifies output as SAFE/UNSAFE [D6 Output Sanitizer] — regex redacts PII/credentials ↓ [Response to User] Components: - RAG: in-memory embeddings, vectors via Ollama (bge-m3) - MCP Server: MCP protocol via Streamable HTTP — tools do NOT filter by status - Tool discovery: dynamic via session.list_tools() — no hardcoded schema - Connect from Claude Code: claude mcp add --transport http pandora-videos http://localhost:55001/mcp
[Usuário] ↓ [D1 Input Filter] — regex: SQL/XSS/delimitadores/credenciais [D2 Input Judge] — LLM classifica input como SAFE/UNSAFE ↓ [RAG — bge-m3 (in-memory)] — recupera contexto dos documentos [D3 SP Lock] — appenda proteção ao system prompt [D4 SP Alignment] — appenda alinhamento ao system prompt ↓ [LLM — Ollama] — gera resposta / aciona tools ↓ [MCP Client SSE] ──→ [MCP Server :55001] ──→ [catalog.json + /videos/] ↓ [D5 Output Judge] — LLM classifica output como SAFE/UNSAFE [D6 Output Sanitizer] — regex redacta PII/credenciais ↓ [Resposta ao Usuário] Componentes: - RAG: embeddings em memória, vetores via Ollama (bge-m3) - MCP Server: protocolo MCP via Streamable HTTP — tools NÃO filtram por status - Tool discovery: dinâmica via session.list_tools() — sem schema hardcoded - Conectar no Claude Code: claude mcp add --transport http pandora-videos http://localhost:55001/mcp

03 — Logging System

▾

Introduction

▾ 
Log files:
  Directory: ./logs/  (created automatically on startup)
  Format:    JSONL — one JSON object per line
  Name:      yyyy-mm-dd_HH-MM-SS.jsonl  (one file per session)

Fields per entry:
  ts          ISO8601 timestamp (UTC)
  request_id  Short UUID of 8 chars — same value for all entries of a request
  src         Source: CHAT · D1 · D2 · RAG · D3 · D4 · APP · MCP · D5 · D6
  action      Action performed (e.g. USER_INPUT, BLOCKED, LLM_REQUEST…)
  detail      Operation details
  elapsed_ms  Operation time in milliseconds
Arquivos de log:
  Diretório: ./logs/  (criado automaticamente no startup)
  Formato:   JSONL — um JSON object por linha
  Nome:      yyyy-mm-dd_HH-MM-SS.jsonl  (um arquivo por sessão)

Campos de cada entry:
  ts          ISO8601 timestamp (UTC)
  request_id  UUID curto de 8 chars — mesmo valor para todas as entries de um request
  src         Origem: CHAT · D1 · D2 · RAG · D3 · D4 · APP · MCP · D5 · D6
  action      Ação executada (ex: USER_INPUT, BLOCKED, LLM_REQUEST…)
  detail      Detalhes da operação
  elapsed_ms  Tempo da operação em milissegundos

Using log_viewer.py

▾ 
  Colorized script that follows the most recent log in real time.
  Colors by source/action (the entire line appears in the corresponding color):
    CYAN      CHAT                               — user input and final response
    WHITE     APP                                — LLM calls (LLM_REQUEST · LLM_RESPONSE)
    YELLOW    RAG                                — semantic search and chunk retrieval
    BLUE      MCP                                — tool discovery and tool calls
    GREEN     PASSED · SAFE · CLEAN              — D1·D2 (passed), D5 (safe), D6 (clean)
    RED       BLOCKED · UNSAFE · REDACTED · ERROR  — D1·D2 (blocked), D5 (unsafe), D6 (redacted), APP (error)
    MAGENTA   D3 · D4                            — always APPLIED when active (modify the system prompt)

  Note: D1·D2·D5·D6 only generate entries when enabled in Admin.
        D3·D4 generate APPLIED on each request while active.
  Script colorido que acompanha o log mais recente em tempo real.
  Cores por origem/ação (a linha inteira aparece na cor correspondente):
    CIANO     CHAT                               — input do usuário e resposta final
    BRANCO    APP                                — chamadas ao LLM (LLM_REQUEST · LLM_RESPONSE)
    AMARELO   RAG                                — busca semântica e recuperação de chunks
    AZUL      MCP                                — tool discovery e chamadas de tools
    VERDE     PASSED · SAFE · CLEAN              — D1·D2 (passou), D5 (safe), D6 (clean)
    VERMELHO  BLOCKED · UNSAFE · REDACTED · ERROR  — D1·D2 (bloqueio), D5 (unsafe), D6 (redacted), APP (error)
    MAGENTA   D3 · D4                            — sempre APPLIED quando ativos (modificam o system prompt)

  Nota: D1·D2·D5·D6 só geram entradas quando estão habilitados no Admin.
        D3·D4 geram APPLIED a cada request enquanto ativos.
Automatically opens the most recent log:
python log_viewer.py
Specify a file:
python log_viewer.py logs/2026-05-06_10-00-00.jsonl

Using tail

▾
All entries:
tail -f logs/*.jsonl
MCP calls only:
tail -f logs/*.jsonl | jq 'select(.src == "MCP")'
Blocks only (D1 or D2):
tail -f logs/*.jsonl | jq 'select(.action == "BLOCKED")'
All entries for a specific request:
tail -f logs/*.jsonl | jq 'select(.request_id == "a1b2c3")'

04 — Defenses

▾

D1 Input Filter

▾ 
  Type: deterministic (regex)
  What it does: detects SQL/XSS/shell injection, LLM control delimiters
             (ChatML, Llama tags, DEBUG:) and credentials in input
  Also detects base64-encoded versions
  Limitation: does not detect injection in natural language — that is D2's job
  Tipo: determinístico (regex)
  O que faz: detecta SQL/XSS/shell injection, delimitadores de controle de LLM
             (ChatML, Llama tags, DEBUG:) e credenciais no input
  Detecta também versões codificadas em base64
  Limitação: não detecta injection em linguagem natural — isso é trabalho do D2

D2 Input Judge

▾ 
  Type: LLM-based
  What it does: second model classifies input as safe/unsafe via RULES array
             detects: prompt injection, jailbreak, DAN, credential extraction,
             cross-tenant access, attempts to reveal the system prompt
  Limitation: small model can be inaccurate; additional latency; fail-open
  Tipo: LLM-based
  O que faz: segundo modelo classifica o input como safe/unsafe via RULES array
             detecta: prompt injection, jailbreak, DAN, extração de credenciais,
             acesso cross-tenant, tentativas de revelar o system prompt
  Limitação: modelo pequeno pode ser impreciso; latência adicional; fail-open

D3 SP Lock

▾ 
  Type: prompt engineering
  What it does: appends "CRITICAL SECURITY INSTRUCTION" block to system prompt
             forbids revealing prompt/credentials, defines default response for
             extraction attempts, prevents social engineering via false authority
  Limitation: LLM may ignore conflicting instructions under injection pressure
  Tipo: prompt engineering
  O que faz: appenda bloco "CRITICAL SECURITY INSTRUCTION" ao system prompt
             proíbe revelar prompt/credenciais, define resposta padrão para
             tentativas de extração, impede social engineering via falsa autoridade
  Limitação: o LLM pode ignorar instruções conflitantes sob pressão de injection

D4 SP Alignment

▾ 
  Type: prompt engineering
  What it does: appends "SECURITY ALIGNMENT" block to system prompt
             restricts scope to platform domain, prevents roleplay,
             RAG poisoning (instructions in retrieved documents) and memory poisoning
  Limitation: same as D3 — prompt engineering is advice, not enforcement
  Tipo: prompt engineering
  O que faz: appenda bloco "ALINHAMENTO DE SEGURANÇA" ao system prompt
             restringe escopo ao domínio da plataforma, impede roleplay,
             RAG poisoning (instruções em documentos recuperados) e memory poisoning
  Limitação: mesma limitação do D3 — prompt engineering é conselho, não enforcement

D5 Output Judge

▾ 
  Type: LLM-based
  What it does: classifies LLM output before serving to user
             detects: credentials, PII, system prompt, infrastructure, code injection
             returns redacted version if unsafe
  Limitation: additional latency (second LLM call); fail-open on errors
  Tipo: LLM-based
  O que faz: classifica o output do LLM antes de servir ao usuário
             detecta: credenciais, PII, system prompt, infraestrutura, code injection
             retorna versão redactada se unsafe
  Limitação: latência adicional (segunda chamada ao LLM); fail-open em erros

D6 Output Sanitizer

▾ 
  Type: deterministic (regex)
  What it does: sanitization pipeline — HTML escape (anti-XSS), URL removal
             (anti-exfiltration), CPF/email/phone/salary masking (PII),
             known credential redaction and generic patterns,
             base64 secret detection (anti-evasion)
  Limitation: regex does not catch data in alternative format (spelled out, rot13, etc.)
  Tipo: determinístico (regex)
  O que faz: pipeline de sanitização — HTML escape (anti-XSS), remove URLs
             (anti-exfiltração), redacta CPF/email/telefone/salários (PII),
             redacta credenciais conhecidas e padrões genéricos,
             detecta segredos em base64 (anti-evasão)
  Limitação: regex não pega dados em formato alternativo (soletrado, rot13, etc.)
